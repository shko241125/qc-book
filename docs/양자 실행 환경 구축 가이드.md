# 양자 실행 환경 구축 가이드

Nov 11, 2026 · @gosh

## 1. 요약

가능하다. 내 컴퓨터에서 Claude Code로 책 폴더를 열고, IBM Quantum의 무료 Open 플랜에 가입하면 설치부터 첫 실기 제출까지 30분 안에 간다(장치 대기열은 별도). 돈은 들지 않는다.

1. 묶음을 풀어 `qc-book` 폴더를 Git 저장소로 만든다(8절).
2. `bash env/setup.sh`로 SDK를 설치하고 점검 표를 본다(5절).
3. IBM Quantum에 가입해 us-east에 Open 인스턴스와 API 키를 만든다(6절).
4. `python env/run_ibm.py`로 Bell 회로를 제출하고 결과를 받는다(6절).
5. 스니펫 보고서와 실행 결과를 책에 반영한다(12절).

한눈에 보는 사실.

- **무료 분량**: IBM Open 플랜은 28일마다 QPU 10분이다. 책에 필요한 작은 회로 수십 개를 돌리기에 넉넉하다.
- **지금 막혀 있던 이유**: 이 채팅 작업 환경은 패키지 설치용 네트워크가 꺼져 있고, 계정 가입은 본인만 할 수 있다(2절).
- **준비해 둔 것**: 설치 스크립트, SDK 점검, 본문 스니펫 37개를 뽑아 돌리는 도구, IBM·Braket 제출 스크립트, Docker·Codespaces 설정, Claude Code 작업 규칙.
- **아직 확인되지 않은 것**: 키트에서 SDK를 부르는 부분은 이 환경에서 돌려 볼 수 없었다. 첫 설치와 첫 제출이 그 검증이다.

## 2. 지금 작업 환경에서 안 되는 것

지금까지 책을 쓴 환경은 두 가지가 막혀 있어서 SDK 코드가 모두 "작성됨, 미실행"으로 남았다.

| 막힌 것 | 이유 | 푸는 방법 |
| --- | --- | --- |
| `pip install` | 이 계정의 채팅 작업 환경은 셸의 외부 네트워크가 꺼져 있다 | 네트워크 설정에서 패키지 설치를 허용한다(새 대화부터 적용). 또는 아래 3절의 다른 환경으로 옮긴다 |
| 양자 장치 API 호출 | 패키지 설치를 허용해도 열리는 곳은 패키지 저장소와 GitHub뿐이다. `quantum.cloud.ibm.com` 같은 장치 주소는 따로 열어야 한다 | 주소를 직접 고를 수 있는 환경(Claude Code 클라우드 환경의 Custom 설정, 내 컴퓨터, Codespaces)을 쓴다 |
| 계정 생성 | 가입에는 본인 이메일 인증과 약관 동의가 필요하고, 유료 경로는 결제 수단이 필요하다 | 본인이 직접 가입한다. 6절에 화면 순서를 적었다 |

그래서 이 가이드는 두 부분으로 되어 있다. 미리 만들어 둔 것은 환경 키트(설치 스크립트, 버전 고정 파일, 점검 스크립트, 장치 실행 스크립트)이고, 사용자가 직접 해야 하는 것은 계정 가입과 첫 설치·실행이다. 키트의 스크립트는 문법 검사와 numpy 경로까지만 확인했고, SDK를 실제로 불러 돌려 보지는 못했다.

## 3. 어디서 돌릴 것인가

내 컴퓨터에서 Claude Code를 쓰는 것이 제일 단순하다. 네트워크 제한이 없고, API 키가 내 컴퓨터 밖으로 나가지 않으며, 책 폴더를 그대로 작업 폴더로 쓴다. 다른 컴퓨터에서도 이어서 하려면 저장소를 GitHub에 올리고 Codespaces나 Claude Code 클라우드 세션을 보조로 둔다.

| 환경 | SDK 설치 | 장치 API 호출 | 자원 | 비용 | 이럴 때 쓴다 |
| --- | --- | --- | --- | --- | --- |
| Claude Code, 내 컴퓨터(터미널·데스크톱 앱) | 제한 없음 | 제한 없음 | 내 컴퓨터. NVIDIA GPU가 있으면 CUDA-Q GPU 가속 | Claude 구독만 | 주 작업 환경. 권장 |
| Claude Code 클라우드 세션(claude.ai/code) | 기본값 Trusted가 PyPI를 허용한다 | Custom으로 장치 주소를 추가하거나 Full로 둔다 | 약 4 vCPU, 16 GB RAM, 30 GB 디스크. GPU 없음 | Pro·Max·Team 플랜에 포함 | 컴퓨터를 켜 두지 않고 긴 작업을 맡길 때. GitHub 저장소가 필요하다 |
| GitHub Codespaces | 제한 없음 | 제한 없음 | 2코어 또는 4코어 | 개인 계정 무료 분량 월 120 코어시간·15 GB. 초과분 2코어 $0.18/시간 | 브라우저만 있는 곳에서. 키트의 devcontainer가 자동 설치한다 |
| qBraid Lab | 주요 SDK 환경이 미리 설치돼 있다 | 자체 크레딧으로 여러 장치에 제출 | 무료 플랜 월 100 CPU시간, 15 GB | 무료. 장치 실행은 크레딧(100크레딧 = $1) | 설치 없이 노트북으로 빨리 확인할 때 |
| Docker 이미지 | 이미지를 만들 때 한 번 | 이미지를 돌리는 곳의 네트워크를 따른다 | 돌리는 컴퓨터 | 없음 | 같은 환경을 여러 컴퓨터에 똑같이 둘 때. 인터넷이 없는 곳에는 `docker save`로 옮기며, 그 경우 시뮬레이터만 된다 |
| 지금의 채팅 작업 환경 | 설정에서 네트워크를 켜면 패키지 저장소가 열린다 | 장치 주소를 따로 허용해야 한다 | 세션마다 새로 설치 | Claude 구독만 | 책 본문·문서 작업. SDK 스니펫 검산까지는 가능하지만 장치 실행 경로로는 권하지 않는다 |

읽는 법. Claude Code 클라우드 세션의 네트워크 단계는 None, Trusted, Full, Custom 네 가지다. Trusted의 허용 목록에 `pypi.org`와 `files.pythonhosted.org`가 들어 있어 `pip install`은 바로 된다. 설치 스크립트로 깔 패키지는 환경 캐시에 남아 다음 세션에서 다시 깔지 않는다. 지금의 채팅 환경은 설정의 Capabilities에서 네트워크를 켤 수 있지만, 추가한 도메인이 적용되지 않는다는 사용자 보고가 여러 건 있어 장치 실행에는 쓰지 않는 편이 안전하다.

출처: [Claude Code 클라우드 환경 문서](https://code.claude.com/docs/en/cloud-environments.md), [Claude 도움말: 네트워크 설정](https://support.claude.com/en/articles/12111783), [GitHub Codespaces 과금](https://docs.github.com/en/billing/concepts/product-billing/github-codespaces), [qBraid 요금](https://qbraid.com/pricing).

읽는 법.

- **IBM의 10분은 생각보다 넓다.** 과금되는 것은 대기 시간이 아니라 QPU가 실제로 돈 시간이다. 14장의 계산으로는 샷 하나가 약 255 µs라 4,000샷 회로가 약 1초이고, 14장 회로 전체가 5\~6초에 작업당 오버헤드가 붙어 수십 초다. 실행 스크립트가 작업마다 실제 사용량을 찍으므로 첫 실행에서 확인한다.
- **Braket 비용은 샷 수로 정해진다.** 1,000샷 기준으로 Rigetti Cepheus $0.73, IQM Garnet $1.75, IonQ Forte $80.30이다. 이온 트랩은 샷 수를 100 안팎으로 잡아야 한다.
- **IBM 유료 가격과 Azure 가격**은 공급사 페이지가 아니라 [가격 정리 사이트](https://quantumcomputingcost.com/ibm-quantum-pricing/)에서 읽었다(IBM은 2026년 11월 7일 확인분). 결제 전에 공급사 페이지를 다시 본다.
- **확인하지 못한 것.** IBM Open 플랜 가입에 카드가 필요한지는 문서에 없었다. IQM 크레딧 한 개의 값과 Quantinuum의 개인 가입 경로도 확인하지 못했다. Google은 공개 장치 접근이 없어 Cirq는 시뮬레이터와 다른 회사 장치(IQM, IonQ)로만 돌린다(이 줄은 조사하지 않고 알고 있는 내용을 적었다).

## 5. SDK 설치

책 폴더(`qc-book/`)에 환경 키트를 넣어 두었다. 저장소 루트에서 명령 세 줄이면 설치와 점검이 끝난다.

```bash
bash env/setup.sh            # .venv 생성 → SDK 설치 → 설치된 버전 기록 → 점검
source .venv/bin/activate
python env/smoke_test.py     # SDK마다 Bell 상태를 만들어 "통과"를 찍는다
```

**준비물.** Linux, macOS, 또는 Windows의 WSL2. Python은 3.11 이상이어야 하고 3.12를 권한다. Cirq 1.7과 CUDA-Q 0.16이 3.11 이상을 요구하고, CUDA-Q 문서가 최신 Python에서의 문제를 언급하며 3.11·3.12를 권하기 때문이다. 책의 numpy 스크립트는 3.13에서 돌렸고 3.12에서도 그대로 돈다.

| 키트 파일 | 하는 일 |
| --- | --- |
| `env/setup.sh` | 가상환경을 만들고 SDK를 설치한 뒤 실제 설치된 버전을 `requirements/lock-날짜.txt`에 적는다. 옵션: `--hardware`(Braket SDK), `--gpu`(CUDA-Q), `--no-venv` |
| `requirements/sdk.txt` | Qiskit, Qiskit Aer, qiskit-ibm-runtime, PennyLane, Cirq, QuTiP, qutip-qip, Qualtran의 버전 범위 |
| `env/smoke_test.py` | SDK마다 Bell 상태 확률을 numpy 기준값과 대조하고, 큐비트 순서(빅·리틀 엔디안)를 확인한다 |
| `env/test_all.sh` | 모든 장의 numpy 검증 스크립트를 다시 돌린다. SDK가 없어도 된다 |
| `env/extract_snippets.py`, `env/run_snippets.py` | 본문의 SDK 코드 블록 37개를 파일로 뽑아 하나씩 돌리고 `runs/snippets-날짜.md`에 통과·실패 표를 남긴다 |
| `env/run_ibm.py`, `env/run_braket.py` | 장치 실행. `--local`은 계정 없이 시뮬레이터로 같은 흐름을 확인한다 |
| `Dockerfile`, `.devcontainer/` | Docker 이미지와 Codespaces 자동 설치 |
| `CLAUDE.md` | Claude Code가 읽는 작업 규칙(구조, 명령, 규약, 하지 말 것) |

**버전.** 2026년 11월 11일에 확인한 최신 배포는 Qiskit 2.6.2(11월 5일), Cirq 1.7.0, PennyLane 0.45.1, CUDA-Q 0.16.0.post1이다. 책의 Qiskit 스니펫은 2.5.x 기준으로 썼으므로 범위를 `>=2.5,<3`으로 잡았다. 나머지는 Qiskit Aer 0.18.2, qiskit-ibm-runtime 0.52.0, QuTiP 5.3.1, qutip-qip 0.4.2, Qualtran 0.7.0이다(검토자가 PyPI에서 확인). 빨리 바뀌는 패키지에는 상한을 두었다. 설치 뒤 잠금 파일에 찍힌 값이 책의 "출처와 환경"에 적을 버전이다.

**GPU.** CUDA-Q는 GPU 없이도 설치되고 CPU로 돈다. GPU 가속은 Linux와 NVIDIA GPU에서만 되며 macOS(Apple silicon)는 CPU 전용이다. `bash env/setup.sh --gpu`로 더한다.

**확인한 범위.** 키트의 파이썬 파일은 문법 검사를 통과했고, 점검 스크립트는 SDK가 없는 환경에서 "미설치" 표를 정상으로 냈으며, 스니펫 추출은 37개를 뽑았다(Qiskit 16, PennyLane 7, Cirq 7, QuTiP 5, CUDA-Q 1, Qualtran 1). SDK를 부르는 부분은 돌려 보지 못했다. 대신 독립 검토자가 호출 하나하나를 공식 문서와 대조했고, 지적 32건(첫 실행에서 실패했을 것 4건 포함)을 반영했다. 그래도 실행 검증은 아니므로, 첫 설치에서 점검 표에 "오류"가 뜨면 그 줄의 메시지를 그대로 알려 주면 된다.

## 6. 첫 실기 실행 — IBM Quantum

가입부터 첫 결과까지 일곱 단계다. 1\~4는 브라우저에서 본인이 하고, 5\~7은 터미널에서 한다.

1. **IBM Cloud 계정을 만든다.** [quantum.cloud.ibm.com](https://quantum.cloud.ibm.com/)에 들어가 IBMid 또는 Google 계정으로 로그인한다. 계정이 없으면 화면이 가입을 안내한다.
2. **지역을 us-east로 맞춘다.** 위쪽 계정 전환기에서 계정과 지역을 확인한다. Open 플랜 인스턴스는 us-east에만 만들 수 있다.
3. **인스턴스를 만든다.** Instances 페이지에서 Create instance를 누르고, 이름을 적고, 요금제로 Open을 고른 뒤 끝까지 넘긴다. 만들어진 인스턴스의 CRN(`crn:v1:`로 시작하는 긴 문자열)을 복사해 둔다.
4. **API 키를 만든다.** 대시보드에서 API 키를 만들고 바로 안전한 곳에 복사한다. 키는 다시 보여 주지 않는다.
5. **계정 없이 흐름부터 확인한다.**

   ```bash
   python env/run_ibm.py --local
   ```

   Aer 시뮬레이터로 Bell 회로를 돌려 비트열 분포와 이상 분포와의 거리(TVD)를 찍고 `runs/`에 JSON을 남기면 정상이다.
6. **키를 저장하고 장치를 본다.**

   ```bash
   python env/run_ibm.py --save     # 키와 CRN을 물어 이 컴퓨터에 저장(화면에 보이지 않는다)
   python env/run_ibm.py --list     # 쓸 수 있는 장치, 큐비트 수, 대기열
   ```

   내 컴퓨터가 아닌 곳(Codespaces, 클라우드 세션)에서는 저장하지 말고 환경 변수 `QISKIT_IBM_TOKEN`, `QISKIT_IBM_INSTANCE`로 넘긴다.
7. **제출한다.**

   ```bash
   python env/run_ibm.py --circuit bell          # 제출 계획만 보여 준다
   python env/run_ibm.py --circuit bell --yes    # 가장 한가한 장치에 1,024샷
   ```

   대기열에 따라 몇 분에서 몇 시간이 걸린다. 중간에 끊겨도 `--fetch <작업 ID>`로 결과를 다시 받는다.

스크립트가 하는 일을 코드로 줄이면 다음과 같다. 책의 다른 회로를 올릴 때도 이 네 단계(연결, 장치에 맞게 변환, 제출, 결과 읽기)는 같다.

```python
# qiskit>=2.5, qiskit-ibm-runtime>=0.42,<0.53 — 작성됨, 미실행 (0.50부터 SamplerV2는 폐기 예정)
from qiskit import QuantumCircuit
from qiskit.transpiler import generate_preset_pass_manager
from qiskit_ibm_runtime import QiskitRuntimeService, SamplerV2 as Sampler

service = QiskitRuntimeService()                      # --save 로 저장한 계정
backend = service.least_busy(operational=True, simulator=False, min_num_qubits=2)

qc = QuantumCircuit(2); qc.h(0); qc.cx(0, 1); qc.measure_all()
isa = generate_preset_pass_manager(optimization_level=1, backend=backend).run(qc)   # 장치의 게이트와 연결에 맞게 변환

job = Sampler(mode=backend).run([isa], shots=1024)
counts = job.result()[0].data.meas.get_counts()       # Qiskit 순서(오른쪽이 q0)
print(counts, job.usage())                            # 사용한 QPU 초
```

**결과 읽는 법.** 이상적인 Bell 상태는 `00`과 `11`이 반반이다. 실기에서는 `01`과 `10`이 몇 퍼센트 섞이며, 이 비율이 14장의 잡음 모형이 예측한 값과 비교할 "실측"이다. 결과 파일에는 장치 이름, 작업 ID, 변환 뒤의 2큐비트 게이트 수와 깊이, 비트열 분포(Qiskit 순서와 책의 순서 둘 다), 사용한 QPU 초가 들어간다.

**14장 회로 올리기.** Bell로 흐름을 확인했으면 14장에 이미 있는 제출 스크립트를 쓴다. GHZ, Bernstein–Vazirani, Grover, QPE 네 회로를 한 작업으로 묶어 4,000샷씩 돌리고, HVA 에너지를 따로 추정한다.

```bash
cd ch14
python ch14_submit.py fake     # 가짜 Heron 장치의 보정 데이터로 로컬 실행. 계정·네트워크 불필요
python ch14_submit.py real     # 실제 제출. 결과와 사용한 QPU 초가 ch14_record_real.json 에 남는다
```

`fake`의 결과는 14장의 numpy 잡음 모형과 비교할 두 번째 예측이고, `real`의 결과가 14장 표의 비어 있는 "QPU 실측"과 "사용 시간" 열을 채운다. 이 스크립트도 아직 돌려 본 적이 없으므로 `fake`에서 나는 오류부터 잡는다.

## 7. 다른 장치 경로

IBM으로 흐름을 익힌 뒤, 초전도가 아닌 장치가 필요할 때만 더한다. 유료 경로는 제출 전에 예상 비용을 보여 주고 한도를 넘으면 멈추도록 스크립트를 짰다.

**AWS Braket.**

1. AWS 계정을 만들고 결제 수단을 등록한다. 콘솔에서 Amazon Braket을 열어 서비스 사용에 동의한다.
2. Braket 권한이 있는 사용자의 액세스 키를 만들고 `aws configure`로 넣는다.
3. 설치와 실행.

   ```bash
   bash env/setup.sh --hardware
   python env/run_braket.py --local                          # 계정 없이 흐름 확인
   python env/run_braket.py --list                           # 지금 온라인인 QPU와 ARN
   python env/run_braket.py --device <ARN> --shots 100       # 예상 비용만 본다
   python env/run_braket.py --device <ARN> --shots 100 --yes --max-usd 2
   ```

이 절차의 1\~2는 조사하지 않고 일반적인 AWS 사용법을 적은 것이다. 화면 이름은 [Braket 시작 안내](https://aws.amazon.com/braket/getting-started)를 따른다. QPU는 정해진 시간대에만 열리므로 제출 뒤 결과가 한참 뒤에 올 수 있다.

**그 밖의 경로.**

| 경로 | 언제 쓰나 | 시작하는 법 |
| --- | --- | --- |
| IonQ Quantum Cloud | 이온 트랩 장치의 잡음 모형을 무료 시뮬레이터로 보고 싶을 때 | [cloud.ionq.com](https://docs.ionq.com/user-manual/accounts.md)에서 가입하고 API 키를 만든 뒤 `pip install qiskit-ionq`로 따로 설치해 제출한다. 키는 환경 변수 `IONQ_API_KEY`에 둔다 |
| IQM Resonance | IBM과 다른 초전도 장치(정사각 격자 연결)에서 같은 회로를 비교할 때 | [IQM Resonance](https://iqm.tech/products/iqm-resonance/)에서 무료 가입. Starter 플랜의 월 크레딧으로 시작한다. Qiskit·Cirq·CUDA-Q를 지원한다 |
| qBraid Lab | 설치 없이 노트북에서 여러 SDK를 바로 써 보거나, 한 계정으로 여러 회사 장치에 제출할 때 | [qBraid](https://qbraid.com/pricing)에 가입해 Lab을 연다. 책 폴더는 Git으로 내려받는다 |

Cirq와 PennyLane 스니펫은 장치 없이 각자의 시뮬레이터로 검산하는 것으로 충분하다. 책이 두 SDK를 병기하는 목적이 "같은 회로를 다른 문법으로 쓴다"이지 "다른 장치에서 돌린다"가 아니기 때문이다.

## 8. Claude Code로 옮기기

책 폴더를 Git 저장소로 만들면 어느 환경에서든 같은 상태로 이어갈 수 있다. 폴더에 넣어 둔 `CLAUDE.md`가 지금까지의 작업 규칙(빅 엔디안, 숫자는 스크립트에서만, "예측"과 "실측" 표시, 비밀을 커밋하지 않기, 묻지 않고 장치에 제출하지 않기)을 Claude Code에 전한다.

**공통 준비 — 저장소 만들기.**

```bash
unzip qc-book-env-kit-2026-11-11.zip && cd qc-book
git init && git add -A && git commit -m "책 원고 0~19장과 실행 환경 키트"
# 다른 컴퓨터와 클라우드에서도 쓰려면 GitHub에 비공개 저장소를 만들어 올린다
git remote add origin git@github.com:<계정>/qc-book.git && git push -u origin main
```

**경로 A — 내 컴퓨터의 Claude Code(권장).**

1. Claude Code를 설치한다. 설치 방법은 운영체제마다 다르므로 [공식 문서](https://code.claude.com/docs/llms.txt)의 설치 안내를 따른다.
2. `qc-book` 폴더에서 Claude Code를 연다. `CLAUDE.md`를 읽고 시작한다.
3. 첫 요청으로 이렇게 맡긴다: "`bash env/setup.sh`를 돌리고 점검 표를 보고해 줘. 그다음 스니펫을 뽑아 돌리고, 실패를 API 변경·스니펫 오류·혼자 돌지 않는 조각으로 나눠 줘."
4. 장치 실행은 6절의 순서대로 직접 키를 저장한 뒤 요청한다. 키는 대화에 붙여 넣지 않는다.

**경로 B — Claude Code 클라우드 세션.** Pro·Max·Team 플랜에서 쓸 수 있고 GitHub 저장소를 복제해서 시작한다. [claude.ai/code](https://claude.ai/code)의 환경 설정 대화상자에서 세 가지를 넣는다.

| 설정 칸 | 넣을 값 |
| --- | --- |
| Network access | SDK 검산만 할 때는 기본값 Trusted 그대로. 장치에 제출하려면 Custom에 기본 목록을 포함하고 `quantum.cloud.ibm.com`, `iam.cloud.ibm.com`, `*.cloud.ibm.com`을 더한다 |
| Environment variables | `QISKIT_IBM_TOKEN=...`, `QISKIT_IBM_INSTANCE=crn:v1:...`, `BASH_DEFAULT_TIMEOUT_MS=600000`(긴 스크립트용, 10분) |
| Setup script | 키트의 `env/claude_cloud_setup.sh` 내용을 붙여 넣는다. 설치 결과는 환경 캐시에 남는다 |

Trusted의 허용 목록에는 IBM Quantum 주소가 없고, 필요한 주소의 전체 목록은 문서에서 확인하지 못했다. 설치 스크립트는 5분쯤 안에 끝나야 캐시에 남는다. 제출이 막히면 오류에 나온 주소를 더하거나, 그 환경만 Full로 둔다. 환경 변수에 넣은 키는 세션이 돌리는 모든 명령이 읽을 수 있으므로, 이 환경은 이 저장소 전용으로 쓴다.

**경로 C — 이 대화를 내 컴퓨터에 연결.** Claude 데스크톱 앱에서 이 대화를 열어 컴퓨터에 연결하면, 지금까지의 맥락을 그대로 둔 채 연결한 폴더에서 설치와 실행을 맡길 수 있다. 새 도구를 익히지 않고 가장 빨리 돌려 보는 길이다. 연결이 안 된 상태에서는 이 대화가 사용자 컴퓨터의 파일에 닿지 못한다.

**어느 경로든 결과를 책으로 되돌리는 방법은 같다.** 세 파일이 근거가 된다: `requirements/lock-날짜.txt`(설치된 버전), `runs/snippets-날짜.md`(스니펫별 통과·실패), `runs/*.json`(장치 실행 결과). 이 대화에서 원고를 계속 쓸 때는 이 파일들을 첨부하면 본문의 "작성됨, 미실행" 표시와 14장의 예측값 옆에 반영한다.

출처: [Claude Code 클라우드 환경 문서](https://code.claude.com/docs/en/cloud-environments.md).

## 9. 비용과 한도

책에 필요한 실행은 무료 분량 안에서 끝난다. 돈이 드는 것은 이온 트랩 같은 다른 방식의 장치를 비교에 넣을 때뿐이다.

| 할 일 | 경로 | 쓰는 양 | 비용 |
| --- | --- | --- | --- |
| numpy 스크립트 전체 재실행 | 내 컴퓨터 또는 Codespaces | 10\~15분 | 없음 |
| SDK 스니펫 37개 검산 | 각 SDK의 시뮬레이터 | 수 분 | 없음 |
| 14장 예측과 실측 비교(회로 4개 × 4,000샷 한 작업 + 에너지 추정 한 작업) | IBM Open 플랜 | 14장의 계산으로 QPU 수십 초. 한도는 28일에 600초 | 없음 |
| 다른 초전도 장치와 비교(선택) | Braket의 IQM Garnet, 1,000샷 | 회로 하나 | $1.75 |
| 이온 트랩과 비교(선택) | Braket의 IonQ Forte, 100샷 | 회로 하나 | $8.30 |

지킬 것 네 가지.

- **작은 것부터.** 첫 제출은 Bell 1,024샷으로 하고, 찍힌 QPU 초를 보고 나머지 계획을 잡는다. 14장의 추정이 맞는지는 실제 값으로 확인한다.
- **유료 장치는 한도를 걸고.** `run_braket.py`는 예상 비용이 `--max-usd`(기본 $2)를 넘으면 제출하지 않는다. AWS 콘솔에도 예산 알림을 걸어 둔다.
- **IBM 유료 전환은 신중히.** Pay-As-You-Go는 QPU 1분에 $96이다. 무료 분량이 모자라면 먼저 180분 추가 행사를 신청한다.
- **Codespaces는 쓰고 나서 멈춘다.** 무료 120 코어시간은 2코어 기준 60시간이다. 결제 수단을 등록하지 않았다면 분량을 다 쓴 뒤에는 더 쓰지 못할 뿐 과금되지 않는다.

## 10. 보안 — API 키 다루기

API 키는 비밀번호와 같다. 두는 곳은 세 군데뿐이다: 내 컴퓨터의 저장 계정(`run_ibm.py --save`), 저장소 루트의 `.env`, 운영체제나 클라우드 환경의 환경 변수.

- **넣지 않는 곳.** 대화창, 코드, 명령줄 인자, 노트북 출력, 커밋, 본문. 키트의 `.gitignore`가 `.env`를 막아 두었지만, 첫 `git push` 전에 `git status`로 한 번 확인한다.
- **내 컴퓨터가 아닌 곳에서는 저장하지 않는다.** IBM 문서도 계정 저장은 개인 노트북 같은 믿을 수 있는 환경에서만 하라고 적는다. Codespaces와 클라우드 세션에서는 환경 변수로 넘긴다.
- **새어 나갔다고 의심되면 바로 폐기한다.** 대시보드에서 그 키를 지우고 새로 만든다. 저장소에 올라갔다면 파일을 지우는 것으로는 부족하다. 이력에 남으므로 키를 폐기하는 것이 먼저다.
- **AWS는 루트 계정의 키를 쓰지 않는다.** Braket 권한만 가진 사용자를 따로 만들고 예산 알림을 건다.
- **원고 저장소는 비공개로 둔다.** 출간 전 원고와 검토 보고서가 들어 있다.

## 11. 문제 해결

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| `pip`가 `cirq-core>=1.7`에 맞는 배포를 못 찾는다 | Python이 3.11보다 낮다 | Python 3.12를 깔고 `.venv`를 지운 뒤 `bash env/setup.sh`를 다시 돌린다 |
| `externally-managed-environment` 오류 | 시스템 Python에 직접 설치하려 했다 | 기본값대로 가상환경을 쓴다. 컨테이너 안에서는 `--no-venv`가 필요한 옵션을 알아서 붙인다 |
| IBM 연결이 계속 `401 Unauthorized` | API 키 대신 다른 토큰을 넣었거나 키가 폐기됐다 | 대시보드에서 API 키를 새로 만들어 `--save`를 다시 한다 |
| 장치 목록이 비어 있거나 인스턴스를 못 찾는다 | 인스턴스가 없거나 지역이 다르다 | Open 인스턴스를 us-east에 만들고 그 CRN을 넣는다 |
| 비트열이 책과 거꾸로다 | Qiskit은 오른쪽이 q0다 | 결과 파일의 `counts_book_order`를 쓴다. 점검 표의 비트 순서 열이 SDK별로 보여 준다 |
| 작업이 오래 대기한다 | 장치 대기열 | 기다린다. 터미널을 닫았다면 `--fetch <작업 ID>`. `--list`로 한가한 장치를 골라 `--backend`로 지정한다 |
| `cudaq`를 불러올 때 비정상 종료 | conda-forge 배포와 최신 Python의 조합 | pip로 설치하고 Python 3.11 또는 3.12를 쓴다 |
| 스니펫이 `NameError`로 실패 | 본문용 조각이라 앞 블록의 변수를 쓴다 | 스니펫 오류가 아니다. 보고서에 "조각"으로 따로 표시된다. 필요한 정의를 덧붙여 혼자 돌게 만든다 |
| 스니펫이 `AttributeError`나 `ImportError`로 실패 | 책은 Qiskit 2.5 기준이고 설치된 것은 2.6이다. 또는 스니펫이 틀렸다 | 해당 SDK의 릴리스 노트를 확인해 둘을 구분한다. 본문을 고칠 때는 버전도 함께 적는다 |
| Claude Code 클라우드 세션에서 명령이 2분에 끊긴다 | 명령 대기 시간의 기본값 | 환경 변수에 `BASH_DEFAULT_TIMEOUT_MS=600000`을 넣는다. 18장 스크립트는 6분이 걸린다 |
| 클라우드 세션에서 장치 호출이 막힌다 | 허용 목록에 없는 주소 | 오류에 나온 주소를 Custom 목록에 더한다 |

**알아 둘 변화.** qiskit-ibm-runtime 0.50(2026년 9월)부터 `SamplerV2`와 `EstimatorV2`가 폐기 예정이고, 대체는 `executor_sampler.Sampler`와 `executor_estimator.Estimator`다. 키트와 14장 코드는 옛 인터페이스를 쓰므로 경고가 뜰 수 있고, `requirements/sdk.txt`가 0.53 미만으로 묶어 두었다. 로컬 실행이 되는 것을 확인한 뒤 새 인터페이스로 옮긴다. 사용량을 읽는 키 이름도 0.51에서 바뀌어, 스크립트는 `job.usage()`를 쓴다. 출처: [qiskit-ibm-runtime 릴리스 노트](https://quantum.cloud.ibm.com/docs/en/api/qiskit-ibm-runtime/release-notes.md).

## 12. 다음 단계

순서대로 하면 된다. 앞의 네 개는 계정이 필요 없다.

- [ ] 묶음을 풀고 `git init`으로 저장소를 만든다
- [ ] `bash env/setup.sh`를 돌려 점검 표를 확인한다
- [ ] `bash env/test_all.sh`로 numpy 스크립트가 새 환경에서도 통과하는지 본다
- [ ] `python env/extract_snippets.py && python env/run_snippets.py`로 스니펫 보고서를 만든다
- [ ] IBM Quantum에 가입해 us-east에 Open 인스턴스와 API 키를 만든다
- [ ] `run_ibm.py`를 `--local`, `--save`, `--list`, `--circuit bell --yes` 순으로 돌린다
- [ ] 잠금 파일, 스니펫 보고서, 실행 결과를 책에 반영한다

**책에 반영되는 곳.** 통과한 스니펫은 첫 줄의 "작성됨, 미실행"을 "실행 완료(날짜)"와 실제 버전으로 바꾼다. 14장은 잡음 모형의 예측 옆에 장치 이름·날짜·작업 ID를 붙인 실측 열을 더한다. 작업계획서의 원칙 4("예측만, 계정이 생기면 실측 추가")가 이것으로 이행된다. 이 가이드의 6\~10절은 5부 "하드웨어·실행 환경" 장의 초안 재료로 쓴다.

**열어 둔 질문.** IBM Open 플랜 가입에 카드가 필요한지, 클라우드 세션에서 IBM 호출에 필요한 주소가 무엇인지는 실제로 해 봐야 안다. 해 보고 알게 된 것을 알려 주면 이 문서를 고친다.
