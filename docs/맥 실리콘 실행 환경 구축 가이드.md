# 맥 실리콘 실행 환경 구축 가이드

2026-11-13 · Claude Code(맥북) 세션. 대상: 저장소 커밋 `d502184` + 반환 묶음 `qc-book-return-2026-11-12`.

이 문서는 WSL2 에서 만든 책 실행 환경(「양자 실행 환경 구축 가이드」 5\~6절)을 Apple silicon 맥에서 같게 만드는 방법을 적는다. 키트(`env/`, `requirements/`)는 그대로 쓰고, 맥에서 달라지는 것만 손댄다. 이 문서를 쓰면서 원고·스크립트는 고치지 않았다.

> **갱신(2026-11-13, 같은 날 뒤).** 아래 1\~2절의 "빈칸"은 메웠다. 실기 묶음(`2026-11-11`, 31개) → 11-11 → 11-12 묶음 순으로 브랜치 `apply-returns-20261111-12` 에 적용해 커밋했다(2.5절). 7.4절의 맥 회귀 실패 넷(ch04·ch16·ch18·ch20)은 맥 고유 문제가 아니라 리눅스(arm64·x86\_64)에서도 나는 스크립트의 약점으로 확인되어 원본을 고쳤다(7.5절).

## 1. 요약

맥에서도 키트 그대로 된다. 다만 **시작하기 전에 막히는 것이 하나** 있다.

- **2026-11-11 반환 묶음이 이 저장소에 없다.** `qc-book-return-2026-11-12` 는 "11-11 묶음을 적용한 상태"를 전제로 바뀐 파일만 담았다. 지금 저장소(그리고 GitHub `origin/main`)는 그 앞 상태다. 20장 전체, `runs/` 의 고정 사본 세 개, 새 `ch14_submit.py`·`run_ibm.py`·`test_all.sh` 등이 빠져 있어, 11-12 묶음만 덮으면 14장·부록 A 스크립트가 멈추고 **`ch14_submit.py real` 이 확인 없이 바로 QPU 에 제출하는 옛 판이 남는다**(2절).
- **설치 자체는 막힘이 없다.** `requirements/sdk.txt`·`hardware.txt`·`gpu.txt` 를 macOS arm64 · Python 3.12 에서 풀어 보니 모든 패키지가 arm64 휠로 풀렸다(3절, `pip install --dry-run` 으로 확인. 설치는 하지 않았다).
- **맥에서 따로 챙길 것은 다섯 가지**: Python 을 어디서 가져올지(지금 PATH 의 첫 `python3` 는 Anaconda), 한글 그림 글꼴(Noto Sans CJK JP 가 없어 그림의 한글이 깨진다), 긴 스크립트와 잠자기·Claude Code 의 명령 시간 제한, 수치 끝자리(BLAS 가 Accelerate), IBM 계정 다시 저장(4절).

순서는 이렇다.

1. 11-11 묶음을 구해 11-12 묶음과 함께 새 브랜치에 적용한다(5절).
2. Homebrew Python 3.12 와 Noto 글꼴을 깔고 `bash env/setup.sh` 를 돌린다(6절).
3. 점검 → numpy 회귀 → 스니펫 → SDK 로컬 경로(Aer·fake) 순으로 확인한다. 여기까지 계정·QPU 가 필요 없다(7절).
4. IBM 계정을 이 맥에 저장하고, QPU 를 쓰지 않는 조회부터 한다. 제출은 승인 뒤에만(8절).

## 3. 이 맥에서 확인한 것

| 항목 | 값 |
| --- | --- |
| 기종 | Apple M1, 메모리 8 GB, 남은 디스크 약 60 GB |
| OS | macOS 26.6.2 (25G83), `uname -m` = `arm64`(Rosetta 아님) |
| 파이썬 | PATH 첫 `python3` = `/opt/anaconda3/bin/python3`(3.12.7, conda `base` 가 켜져 있다). `/usr/bin/python3` 는 Xcode 의 옛 판. Homebrew 파이썬은 없음 |
| 도구 | Homebrew(`/opt/homebrew`), Xcode, git 2.50.1(`core.precomposeunicode=true`), `/bin/bash` 3.2.57, Claude Code(`~/.local/bin/claude`) |
| 글꼴 | Noto Sans CJK JP 없음. Apple SD Gothic Neo, Nanum Gothic 있음 |

확인한 실행.

- **휠 해석.** 스크래치 venv(Python 3.12)에서 `pip install --dry-run --only-binary=:all:` 로 세 요구 파일을 풀었다. `sdk.txt` 187개, `hardware.txt` 201개가 모두 휠로 풀렸고 컴파일이 필요한 것은 없었다(numpy 2.5.4 · scipy 1.18.1 `macosx_14_0_arm64`, qiskit 2.6.2, qiskit-aer 0.18.2 · qutip 5.3.1 `macosx_11_0_arm64`, qiskit-ibm-runtime 0.52.1, amazon-braket-sdk 1.127.8 등). `gpu.txt` 의 `cudaq` 는 휠이 아닌 메타 패키지(sdist)라 `--only-binary` 로는 안 풀리고, 허용하면 `cuda-quantum-cu13 0.16.0` 의 `macosx_13_0_arm64` 휠로 풀린다.
- **bash 3.2.** `env/*.sh` 세 개가 `bash -n` 을 통과했고, 저장소 사본에서 `bash env/test_all.sh ch01 ch03` 이 통과했다(각 1\~2초).
- **한글 글꼴.** 같은 실행에서 스크립트 하나마다 `findfont: Font family 'Noto Sans CJK JP' not found.` 가 170\~200줄 찍히고 `Glyph … missing from font(s) DejaVu Sans` 가 났다. 수치와 통과 여부는 그대로지만 **그림의 한글이 네모로 나온다**.

| 항목 | WSL2 (지금까지) | 맥 | 할 일 |

| 잡파일 | — | `.DS_Store` 가 폴더마다 생긴다(반환 묶음에도 있다) | 복사할 때 빼고, `.gitignore` 에 없으므로 커밋 전에 확인한다 |

- **ch18** — ADAPT 의 기울기 최댓값과 10⁻⁷ 안의 후보는 동점으로 보고 풀 순서의 첫째를 고른다(세 환경의 순서·게이트 수가 같아졌다). 평가 횟수와 HVA 의 n = 6, p = 8·9 줄은 국소 최소·BFGS 경로가 계산기마다 달라 정확한 값 대신 본문의 "수준"·"약"과 대조한다. 본문에 그 사실과 세 환경의 값 범위를 적었다.
- **ch20** — QSVT − 다항식 차의 상한을 배정밀도 ε × 최대 차수(2.2e-16 × 423 ≈ 9.4e-14)에 근거해 1e-13 으로 정했다. 본문은 "10⁻¹³ 미만(반올림 수준)"으로 적었다. **허용 오차를 넓힌 유일한 곳**이며, 원래 값 4e-14 는 한 계산기의 관측값(3.8e-14)에 붙인 것이라 근거가 없었다.

- **부록 A `appA_bv_confirm.py`** — P4(끝에서 보조도 측정)의 잡음 없는 출력은 `01011`·`11011` 이 정확히 반반이다. 1e-12 안의 동점은 모두 적도록 고쳤다(`01011·11011 (각 확률 0.5000)`). 판정 규칙·예측은 그대로다(검사는 데이터 4비트만 본다). `appA_bv_stdout.txt` 는 이 한 줄만 바뀌었다.
- **ch19(맥 고유)** — 특이벡터의 부호는 수학적으로 정해지지 않는다. 같은 numpy 2.5.4 에서 맥은 화자 임베딩 PCA(100×192)의 2·3번째 성분, 8명 대조(200×192)의 3·4·7번째 성분 부호가 리눅스와 반대다(특이값은 같다). ZZ 특성 맵은 x 와 π − x 를 구별하므로 5절 (2) 표(커널 평균, 1-NN, 정렬, 샷 수)가 달라진다 — 예: n = 2 의 1-NN 0.91 → 0.99, n = 10 의 샷 수 5,058 → 4,512. 이 표에는 assert 가 없어 원본은 맥에서도 "통과"로 끝난다. 맥에서는 원본 대신 **`python env/mac/ch19_candidates_mac.py > runs/regress/ch19_candidates_mac.out`** 를 돌린다. 원본을 그대로 실행하되 SVD 의 부호만 기준 환경에서 잰 값으로 맞추며, 출력은 `ch19_stdout.txt` 와 실행 시간 줄 말고는 같다. (원본에 부호 규약을 넣으면 플랫폼과 무관해지지만 본문 표 값이 바뀌므로 저자 결정 사항으로 남긴다.)

**컨테이너에서 돌릴 때.** OpenBLAS 가 코어 수만큼 스레드를 띄워 컨테이너 여럿이 CPU 를 다투면 수십\~백 배 느려진다(ch13 이 맥 49초 → 2시간). `-e OPENBLAS_NUM_THREADS=1` 로 묶는다.
