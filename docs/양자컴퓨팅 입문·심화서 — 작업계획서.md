## 1. 이 문서의 목적과 사용 규칙

이 문서는 책 작업의 단일 진실 원천(single source of truth)이다. 세션이 바뀌거나 구현 시도가 실패해도 §2(불변 원칙), §4(책 구조), §7(상태 보드), §8(결정 기록)이 살아 있으면 작업을 그 자리에서 이어갈 수 있다.

**세션 재개 프로토콜** — 매 세션 시작 시 이 순서대로 따른다.

1. §2를 읽고 바뀌지 않는 원칙을 확인한다.
2. §7에서 상태가 "진행 중" 또는 "다음"인 장을 하나만 고른다. 한 세션에 한 장이 원칙이다.
3. §8의 결정 기록을 읽고, 이미 내린 결정은 다시 묻지 않는다.
4. 장 작업은 §5의 장 템플릿 순서대로 진행하고, 코드는 반드시 실행해 결과(출력·히스토그램·실행 시간)를 본문에 남긴다.
5. 세션 끝에 §7 상태와 §8 결정 기록만 갱신한다. §2\~§6 본문은 §8에 사유를 남긴 뒤에만 고친다.

**문서 수정 규칙**

- §2(불변 원칙)는 사용자가 직접 바꾸자고 한 경우에만 수정한다.
- 참고자료·도구가 늘면 §3 표에 행을 추가한다. 버전은 확인한 날짜와 함께 적는다.
- 장의 추가·삭제·순서 변경은 §4와 §7을 함께 고치고 §8에 한 줄 기록한다.
- 각 장의 본문은 이 문서와 별도의 문서(장당 1개)로 만들고, §7 표에 링크를 건다. 같은 내용을 chNN\_slug.md와 chNN\_slug.html 파일로도 내보내 대화에 첨부한다.

## 2. 책의 목표·독자·범위 — 불변 원칙

**목표(한 줄)**: 게이트 수준의 이해에서 출발해 대표 알고리즘을 직접 구현하고, 새 알고리즘을 찾는 방법론을 세워 실용 알고리즘을 탐색·구현하는 데까지 독자를 데려간다.

**독자**: 선형대수와 Python에 익숙한 엔지니어. 저자 본인이 1호 독자다. 물리학 학위를 가정하지 않고, 양자역학은 회로 언어로 필요한 만큼만 도입한다.

**불변 원칙** — 번호를 유지하며, §8에 사유를 적지 않고는 바꾸지 않는다.

1. 모든 개념은 "게이트 → 회로 → 알고리즘 → 하드웨어" 순서로 올라간다. 추상적 정의보다 2\~3큐비트 회로를 Quirk에서 손으로 먼저 돌려 본다.
2. 모든 알고리즘은 실행 가능한 코드를 동반한다. 수식만 있는 장은 미완성이다.
3. 주 SDK는 Qiskit이다. 비교가 의미 있을 때만 Cirq·PennyLane·CUDA-Q·QuTiP를 같은 알고리즘으로 병기한다. 다섯 SDK를 균등하게 다루지 않는다.
4. 각 알고리즘은 시뮬레이터 결과와 하드웨어 결과(노이즈 포함)를 함께 보인다. 하드웨어 결과는 공개 보정 데이터로 만든 잡음 모형의 예측으로 먼저 싣고, QPU 계정과 네트워크가 생기면 IBM Open Plan의 무료 한도(§3) 안에서 실측을 더한다(2026-11-11 결정).
5. 3부 "알고리즘 발견 방법론"이 책의 중심이다. 1·2부는 그 재료이고, 4부는 그 방법론을 적용한 결과다.
6. 모든 주장에 1차 출처(공식 문서·교과서·논문)를 단다. 블로그·포럼은 직관 보강용으로만 쓰고 출처 등급(§6)을 표시한다.
7. 본문은 한국어, 코드·용어·API 이름은 영어 그대로 쓴다.
8. 각 장은 독립적으로 읽히게 쓴다. 앞 장의 내용은 다시 설명하지 않고 링크로 가리킨다.
9. 각 장 끝에 "학습 노트"(핵심 분기점·처음 접하는 개념·더 깊이 볼 것)를 둔다.

**범위 밖(명시적으로 제외)**: 큐비트 제작 물리(초전도·이온트랩 공정), 양자 오류 정정의 심화 이론(5부에서 실용 관점의 개요만), 양자 암호(QKD), 양자 어닐링 전용 하드웨어.

## 5. 집필 워크플로와 장 템플릿

한 장은 5단계를 거쳐 "완료"가 된다. 단계를 건너뛰지 않고, 각 단계의 산출물이 있어야 다음으로 간다.

1. **구조**: 장의 학습 목표(§4 표의 문장)를 확인하고 소제목 5\~8개를 먼저 쓴다. 산출물: 소제목만 있는 장 문서.
2. **조사**: §3의 A등급 자료에서 정의·API·수치를 가져오고 링크를 단다. B·C등급은 직관 문장에만 쓴다. 산출물: 출처 목록.
3. **초안**: 템플릿 순서로 본문을 쓴다. 코드는 이 단계에서 실제로 실행하고 출력·히스토그램을 본문에 붙인다. 산출물: 실행 결과가 포함된 초안.
4. **덧붙이기**: 비유·아하 모먼트·반례·다른 SDK 병기·연습문제를 추가한다. 산출물: 완성 초안.
5. **검증**: §6 체크리스트를 통과시킨다. 가능하면 본문을 보지 않은 별도 검토자(서브에이전트)가 코드 재실행과 사실 확인을 한다. 산출물: 검토 기록 한 줄(§8).

**장 템플릿** — 모든 장이 같은 순서를 따른다.

1. 한 문단 요약: 이 장이 답하는 질문과 결론.
2. 직관 먼저: 2\~3큐비트 예제를 Quirk 링크로 손으로 돌린다.
3. 정의와 수식: 행렬·상태벡터·유니터리 표기. 수식은 display 블록으로. 끝에 교과서(N&C·KLM) 비교를 둔다.
4. 회로(도구) 구성: 게이트 단위 설명 → numpy 구현(실행 완료) → Qiskit 코드. 2부·4부는 게이트 비용 기록(2큐비트 게이트 수·깊이·T-count)을 함께 적는다.
5. 실행 결과: numpy 검증 스크립트의 출력과 그림. SDK 출력은 실제로 실행한 것만 싣는다.
6. 다른 SDK 대응: Cirq·PennyLane·CUDA-Q·QuTiP 중 비교 가치가 있는 하나만, 고른 이유 한 문장과 함께.
7. 한계와 반례: 고전 시뮬 가능성, 자원 비용, 알려진 비판.
8. 연습문제 3개와 해답. 해답은 각 문제 바로 아래 '해답' 소제목으로 본문에 둔다. 최소 1개는 교과서 변형이다.
9. 학습 노트: 핵심 분기점·처음 접하는 개념·더 깊이 볼 것.
10. 출처와 환경: 출처 목록(등급 표시)과 실행 환경·버전·시드. 하드웨어 실행은 장마다 절을 두지 않고 14장(2부)과 5부에 모은다.

**코드 규칙**

- Python 3.12 이상, 패키지 버전을 장 첫 코드 셀에 고정해 적는다 (`qiskit==2.5.x` 형식).
- 모든 코드는 복사해 그대로 실행되는 완결 스니펫이어야 한다. 생략 표시(`...`)를 쓰지 않는다.
- 난수는 `seed`를 고정한다. 측정 샷 수는 명시한다.
- QPU 실행은 장당 1\~2회, 총 28일 10분 한도를 §7 예산 열에 기록한다. 시뮬레이터로 먼저 완전히 검증한 뒤에만 제출한다.
- CUDA-Q 실행 환경은 3단계다: 기본은 로컬 NVIDIA GPU(`nvidia` 타깃), GPU가 없으면 CPU(`qpp-cpu` 타깃), 20큐비트 이상 대규모는 클라우드(NVIDIA Quantum Cloud 또는 Amazon Braket 백엔드). 코드는 타깃 이름만 바꿔 세 환경에서 모두 돌아가게 쓴다.
- 코드 파일 이름은 `chNN_slug.py`, 노트북은 `chNN_slug.ipynb`, 내보낸 장 문서는 `chNN_slug.md`·`chNN_slug.html`로 통일한다.
